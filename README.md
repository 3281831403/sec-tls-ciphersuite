sec-tls-ciphersuite
===================

容量评审时发现，同一份密码套件配置在测试环境与生产环境被解读成不同的候选集：排除项写了却被重新加回，1.3 套件被当成没有密钥交换，强度排序把 RC4 排在 AES 前面，最小版本把恰好等于下界的套件误杀，导出级套件从禁用名单里漏出。契约要求：冒号分隔的配置串按从左到右的顺序展开，裸名称按前缀匹配清单中的套件，ALL 取全量且保持清单顺序，重复项只保留首次出现；感叹号排除在整串展开完成后统一生效，与其书写位置无关；加号把匹配到的套件整体移到末尾并保持它们此前的相对顺序，不得重排；强度标记对当前已收集的套件按版本优先、再按加密算法、密钥交换、摘要的顺序从强到弱排序，并列项保持原有先后；套件描述由密钥交换、认证、加密、摘要、协议版本五个字段组成，TLS 1.3 套件的密钥交换记为 TLS13 且认证与独立摘要为空，AEAD 套件没有独立摘要，CBC 模式必须在加密字段中可见；策略筛选永不放行 RC4、3DES、NULL 与导出级套件，最小版本为包含式下界，允许与拒绝前缀均按大小写不敏感匹配且拒绝优先，输出保持输入顺序，未知名称忽略；前向保密只在密钥交换为临时或 TLS 1.3 时为真。不变量：筛选结果是输入的子序列且幂等；强度标记的结果与独立强度排序一致；排除项的位置不影响结果；套件清单内不出现重复项。
